# Worktrail 사용법 (2판)

Worktrail 은 에이전트와 한 작업을 **스레드** 단위로 남긴다. 다음 세션이나 다른 에이전트가 코드를 보고
추측하는 대신 그 기록에서 이어받는다. (도구 이름은 `casebook` 그대로다 — 설치된 것을 깨지 않기 위해.)

**시킬 게 없다.** 서버가 붙는 순간 에이전트에게 "언제 무엇을 기록하는가"를 통째로 알려 주고, 규칙 몇 개는
도구 자체가 지킨다 — 주제 없이는 스레드를 못 열고, 다음 차례를 안 적으면 NEXT 를 못 남긴다. 그래서 평소에는
그냥 일하면 된다. 이 문서는 **그 기록을 어떻게 써먹는가**와, 사람만 줄 수 있는 몇 가지를 다룬다.

설치는 운영자에게 받은 URL 한 줄이다(`… /install.sh | sh`). **맥·리눅스·WSL 에서 된다** — 윈도우 네이티브는
아직 아니다(설치기와 실행기가 sh 이고, Codex 등록은 `codex` CLI 가 있을 때만 된다). 그 줄이 클라이언트·서버
주소·에이전트 등록·훅을 한 번에 끝낸다. 업데이트도 같은 줄이다. **URL 이 곧 비밀번호다** — 스크린샷·화면 공유·채팅에 올리지 않는다.

설치가 끝나면 명령 둘을 알려 준다. `~/.casebook/client/bin/casebook-ui` 는 브라우저로 기록을 보는 창이고,
`~/.casebook/client/bin/casebook-backfill` 은 **깔기 전에 한 작업**을 가져온다 — 작업공간 목록을 보여 주고
무엇을 올릴지 고르게 하며, 가져오는 것은 당신이 친 말의 원문뿐이다(에이전트의 말·도구 결과는 가지 않는다).
회사 코드나 비밀이 섞인 폴더는 빼면 된다. 가져온 것은 현황·회고와 섞이지 않고 **과거 기록** 탭과 검색에만 나온다.

---

## 1. 하나만 지키면 되는 것 — 한 작업 = 스레드 하나

스레드는 **한 저장소의 짧은 질문 하나 또는 변경 하나**다. 20분짜리 수정도 스레드다.
대화 주제가 바뀌면 새 스레드다. 에이전트가 알아서 열고 닫는다 — 사람이 볼 것은 "지금 이 얘기가
아까 그 얘기와 같은 일인가" 하나뿐이고, 아니면 한마디 하면 된다("이건 새 스레드로").

이걸 안 지키면 나머지가 전부 무너진다. 한 스레드에 하루치 주제가 쌓이면 나중에 읽을 때
"이 결정이 무엇에 대한 것이었나"를 다시 추측해야 한다 — 기록을 남긴 이유가 사라진다.

스레드를 열 때 에이전트가 **주제** 이름을 묻는다. 기존 것에서 고르거나 새로 준다.
주제는 여러 날에 걸친 하나의 일감이고(예: "원격 문", "결제 장애"), 스레드는 그 안의 한 걸음이다.

## 2. 사람만 줄 수 있는 것 — 셋뿐이다

에러가 났는지, 테스트가 깨졌는지, 커밋이 생겼는지는 기계가 안다. 에이전트가 알아서 남긴다.
사람이 아니면 아무도 줄 수 없는 것은 이 셋이다.

- **판정.** "이거 됐다" / "아니다". 기계는 시도한 것까지만 알고 그게 충분한지는 모른다.
  스레드를 닫는 것도, 결과 한 줄을 쓰는 것도 여기서 나온다.
- **결정.** 내가 정한 것은 에이전트가 정한 것과 무게가 다르다. 말한 대로 "사용자가 정함"으로 남고,
  나중에 뒤집으려면 나만 뒤집을 수 있다. 따로 명령할 필요는 없다 — 대화 중에 정하면 그대로 들어간다.
- **주제 이름.** 새 일감의 이름은 그 사람 머릿속에만 있다. 에이전트가 물어보면 답해 주면 된다.

가설은 결정이 아니다. **세상이 뒤집을 수 있으면 노트, 나만 바꿀 수 있으면 결정**이다.
이 선만 지키면 기록이 낡지 않는다.

### 어긋날 때만 쓰는 한마디

평소엔 필요 없다. 눈에 거슬릴 때만 쓴다.

| 이럴 때 | 이렇게 |
|---|---|
| 한 스레드에 다른 얘기가 쌓일 때 | "이건 새 스레드로" |
| 중요한 출력이 그냥 지나갈 때 | "그거 기록해" |
| 다음 차례를 잘못 잡았을 때 | "그건 내 차례야" / "코덱스한테 넘긴 거야" |
| 키·비밀번호가 화면에 있을 때 | "그건 기록하지 마" |

## 3. 멈출 때가 제일 중요하다 — "다음 손이 누구 것인가"

세션을 닫기 전에 에이전트가 두 줄을 남긴다.

- **NEXT** — 다음에 할 구체적 행동 1~3개
- **차례** — 그 행동을 할 사람이 누구인가: **나** / **어떤 에이전트** / **아무도 아님(보고만 있음)**

차례는 빼먹을 수 없다 — 없으면 도구가 NEXT 를 거부한다. 이게 없으면 내일 화면을 열었을 때
"내가 뭘 해야 하나, 아니면 기다리면 되나"를 매번 다시 판단해야 하기 때문이다.

다만 에이전트가 차례를 틀리게 잡을 수는 있다(자기가 할 일이라고 생각했는데 실은 내 판정이 필요한 경우).
현황에서 이상하면 그때 한마디 하면 된다.

## 4. 기록을 눈으로 보기

```bash
~/.casebook/client/bin/casebook-ui
```

브라우저가 열린다. 끄려면 Ctrl+C. 화면은 내 컴퓨터에만 열리고 토큰은 브라우저에 들어가지 않는다 —
이 명령이 대신 서버와 이야기한다. 그래서 로그인 화면도 없다. 화면은 **읽기 전용**이다.

두 화면이 서로 다른 질문에 답한다.

- **현황** — "지금 뭘 해야 하나." 열린 스레드를 차례별로 본다. 왼쪽에서 *내 차례* 만 걸러 보는 게
  하루를 시작하는 가장 빠른 방법이다. 제목 옆 원 하나가 차례를 나타낸다.
- **회고** — "이 주제가 어떻게 여기까지 왔나." 한 주제의 사건을 시간순으로 전부 본다.
  결정이 왜 그렇게 났는지 되짚을 때 쓴다. 대신 양이 많다 — 지금 할 일을 찾을 때는 현황이 낫다.

스레드의 **증거 · 노트**를 누르면 Worktrail 안에서 원문과 결론을 각각 펼쳐 읽을 수 있다.
증거의 공백·줄바꿈도 그대로 보이며, **스레드로 돌아가기**로 현재 상태에 돌아온다.

주제의 스레드가 전부 닫히면 그 주제는 **완료**로 접힌다. 지우지 않는다.

## 5. 알아 둘 것

- **세션 시작할 때.** Claude Code 는 첫 화면에 열린 스레드가 저절로 뜬다. Codex 는 훅이 없으므로
  세션을 열고 한 번만 말해 준다: *"casebook mcp 참고하고 기록하면서 진행해."* 그 한 번으로 세션 내내
  알아서 기록한다 — 매 요청마다 시킬 필요는 없다. 그 한마디도 빼려면 `~/.codex/AGENTS.md` 에 두 줄을 둔다.
- **대화가 길어져 요약될 때.** 요약에만 남은 관찰은 사라진 것이나 같다. Claude Code 는 요약 직후
  "먼저 기록하라"고 스스로 알린다. 다른 에이전트라면 긴 세션 중간에 한 번 "여기까지 기록해" 라고 한다.
- **커밋은 저절로 붙는다.** 어떤 에이전트든 터미널이든 상관없다. 저장소마다 한 번만:
  `sh ~/.casebook/client/tools/hooks/install_git_hook.sh`
- **에이전트를 섞어 써도 된다.** 같은 기록을 본다. 스레드 연결은 **폴더마다 하나**라, 폴더가 다르면
  서로 무관하고 같은 폴더도 번갈아 쓰면 괜찮다. **같은 폴더에서 동시에** 돌릴 때만 서로의 기록이
  한쪽 스레드로 붙는다 — 동시에 쓸 거면 폴더를 나눈다.
- **내 기록은 내 URL 로만 보인다.** 남의 것은 안 보이고 내 것도 남에게 안 보인다.
  단 한 서버 한 DB 라 운영자는 볼 수 있다.
- **기록은 원문 그대로 남는다.** 키·비밀번호가 든 출력은 "그건 기록하지 마" 라고 한다.
- **안 붙으면** 설치 한 줄을 다시 실행한다. 세션 시작 화면에 `casebook hook … skipped` 가 뜨는 건
  서버가 잠깐 안 닿은 것이고 작업은 그대로 된다.

## 6. 토큰 얼마나 먹나

기록을 남기는 건 에이전트다. 그만큼 토큰이 더 나간다. 하루치 세션(사람 74턴, casebook 호출 130회)으로
tiktoken 으로 실측한 값이다.

**세션 하나당 고정 — 아무것도 안 해도 든다**

| 항목 | 토큰 |
|---|---|
| 도구 정의 23개 (문맥 상주) | 4,800 |
| 서버 안내문 | 460 |
| SessionStart 훅이 넣는 현재 스레드 요약 | 1,300 |
| **합계** | **약 6,600** |

**호출당**

| 도구 | 보낸 것 | 받은 것 | 1회 |
|---|---|---|---|
| add_evidence | 466 | 21 | 490 |
| note_turn | 330 | 25 | 355 |
| decide | 131 | 22 | 150 |
| declare | 97 | 24 | 120 |
| constrain | 93 | 22 | 115 |
| open_thread | 54 | 146 | 200 |
| close_thread | 80 | 111 | 190 |
| search_evidence | 14 | 833 | 850 |
| resume | 7 | 4,787 | 4,800 |

받는 쪽이 큰 것은 `resume` 과 `search_evidence` 둘뿐이다. `resume` 은 세션당 한 번이면 된다.

**하루 총량**

| 쓰는 정도 | 기록 횟수 | 하루 토큰 |
|---|---|---|
| 결정만 남김 | 10~20 | 1만~1만 5천 |
| 보통 | 40~60 | 2만~3만 |
| 실측한 날 | 130 | 6만 |

실측한 날 casebook 몫은 오간 토큰 전체의 **11.6%** 였다 (전체 513,761 중 59,665).
같은 한도로 10번 할 일이 9번이 된다는 뜻이다.

**줄이는 법** — 긴 출력은 `add_evidence_file` 로 파일에 두고 참조만 남긴다.
탐색·잡담 구간에는 스레드를 열지 않는다. `resume` 을 세션 중간에 다시 부르지 않는다.

## 채팅에서만 쓸 때 (Claude.ai · ChatGPT)

설치 없이 같은 URL 을 커넥터로 넣는다. 대신 git 정보(브랜치·커밋 연결)는 안 붙는다.

- Claude.ai: 설정 → 커넥터 → 커스텀 커넥터 추가 → URL 붙여넣기 (OAuth 칸 비움)
- ChatGPT: 설정 → 앱·커넥터 → 고급 → 개발자 모드 → MCP 서버 추가 (인증 없음)
