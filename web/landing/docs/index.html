AI 코딩 에이전트가 일하며 남기는 작업 기록입니다. 다음 세션이 코드에서 추측하지 않고, 멈춘 자리에서 이어 갑니다.

Claude Code나 Codex와 일하다 세션을 닫으면 대화는 사라집니다. 코드와 커밋은 남지만, 무엇을 정했고 왜 그랬는지, 무엇이 안 풀렸고 다음은 누구 차례인지는 코드에 없습니다. Worktrail은 그것을 스레드에 남기고, 새 세션은 그 스레드에서 시작합니다.

MCP 서버 하나와 작은 로컬 창으로 되어 있습니다. 에이전트가 MCP 도구로 기록하고, 사람은 창에서 읽습니다.

어디서부터 볼까요

빠른 시작설치부터 다음 세션에서 이어받기까지 5분. 무엇이 남는가초점, 결정, 증거, 노트, 다음과 차례. 평소 쓰는 법만든 사람이 실제로 치는 말로 보는 하루. MCP 도구에이전트가 쓰는 도구 전부.

에이전트에 붙이기

MCP 등록과 세션 훅까지 끝납니다. 기록은 이 컴퓨터에 남습니다. Python 3.11 이상 또는 uv가 필요합니다.

Claude Code 안에서
/plugin marketplace add jasonethicseo/worktrail
/plugin install worktrail@worktrail

새 버전을 자동으로 받으려면 플러그인의 auto-update를 켭니다.

Codex에는 플러그인이 없으므로 소스에서 깔고 직접 등록합니다.

터미널
git clone https://github.com/jasonethicseo/worktrail.git && cd worktrail
python3 -m venv .venv && .venv/bin/pip install -e ".[mcp]"
mkdir -p ~/.casebook && echo local > ~/.casebook/mode
codex mcp add casebook -- $PWD/.venv/bin/python -m casebook.adapters.mcp_proxy

Claude Code에도 소스에서 붙이려면 마지막 줄 대신 claude mcp add casebook -s user -- $PWD/.venv/bin/python -m casebook.adapters.mcp_proxy를 쓰고, 세션 훅은 sh tools/hooks/install_claude_hooks.sh로 겁니다.

신청 화면에서 서버를 고르면 설치 한 줄을 받습니다. 클라이언트 설치, 찾은 에이전트(Claude Code·Codex) 등록, 훅까지 한 번에 합니다. 업데이트도 같은 줄입니다.

터미널
curl -fsSL <받은 URL>/install.sh | sh -s -- --server
URL이 곧 열쇠입니다. 화면 공유, 스크린샷, 채팅에 올리지 않습니다.

설치 없이 같은 서버를 커넥터로 붙입니다. 호스팅 서버에서만 되고, 브랜치나 커밋 같은 git 정보는 붙지 않습니다.

  • claude.ai: 설정 → 커넥터 → 커스텀 커넥터 추가 → URL 붙여넣기
  • ChatGPT: 설정 → 앱·커넥터 → 고급 → 개발자 모드 → MCP 서버 추가
MCP 서버는 casebook이라는 이름으로 등록됩니다. 처음 이름이고, 이미 설치된 것을 깨지 않으려고 그대로 두었습니다. 에이전트에게는 “casebook”이라고 부르면 됩니다.

윈도우

윈도우에는 sh가 없어서 설치 한 줄이 돌지 않습니다. 대신 신청 화면에서 Windows를 고르면 지시문 주소(…/windows.md)를 줍니다. 그 쪽을 열어 통째로 코딩 에이전트(Claude Code, Codex)에게 붙여 넣으면, 에이전트가 파이썬 실행기, MCP 등록, 훅까지 윈도우에 맞게 설치합니다.

지시문 주소에도 열쇠가 들어 있습니다. 설치 한 줄과 같이 다룹니다. 이 컴퓨터에만 두는 방식(플러그인, 소스 설치)은 윈도우에서는 WSL 안에서만 됩니다.

Codex에서 매번 말하지 않기

Codex에는 세션 훅이 없어서, 세션마다 한 번 “casebook 열린 스레드 보여줘”라고 합니다. 그 한마디도 빼려면 ~/.codex/AGENTS.md에 한 줄을 둡니다. 만든 사람이 실제로 쓰는 줄입니다.

~/.codex/AGENTS.md
사용자의 작업에 대한 정보가 필요할 시 연결된 Worktrail MCP를 활용하여 스레드를 열거나 확인하여 조사 후 필요하다면 기록할 것. Worktrail 을 적극 활용할 것.

커밋 붙이기

Claude Code는 커밋을 스레드에 저절로 붙입니다. 터미널이나 다른 에이전트의 커밋도 붙이려면 그 저장소 안에서 한 번 git 훅을 겁니다.

저장소 안에서
# 서버 설치
sh ~/.casebook/client/tools/hooks/install_git_hook.sh
# 소스 설치 (worktrail 폴더의 것)
sh tools/hooks/install_git_hook.sh

한 작업은 스레드 하나입니다. 여러 날에 걸친 일감은 주제로 묶습니다.

스레드

한 저장소에서의 질문 하나 또는 변경 하나를 끝까지 따라간 것입니다. 20분짜리 수정도 스레드입니다. 정하는 일과 만드는 일은 한 스레드이고, 질문이 바뀔 때만 새로 엽니다.

에이전트가 알아서 열고 닫습니다. 사람이 볼 것은 “지금 이 얘기가 아까 그 얘기와 같은 일인가” 하나뿐이고, 아니면 “이건 새 스레드로”라고 합니다.

한 스레드에 하루치 주제가 쌓이면, 나중에 읽을 때 “이 결정이 무엇에 대한 것이었나”를 다시 추측해야 합니다. 기록을 남긴 이유가 사라집니다.

주제

여러 날, 여러 저장소에 걸친 한 줄기 일감입니다(예: “결제 장애”, “원격 연결”). 스레드는 반드시 어느 주제 아래 열립니다. 에이전트는 기존 주제에서 고르고, 맞는 것이 없을 때만 새 이름을 묻습니다. 주제의 스레드가 다 닫히면 그 주제는 완료로 접힙니다.

폴더와의 연결

스레드는 저장소에 속하고, 지금 어느 스레드를 하는지는 폴더(worktree)마다 하나입니다. 그래서 두 에이전트가 다른 폴더에서 일하면 서로 덮어쓰지 않습니다.

스레드 안에는 뒤집는 주체가 다른 것들이 따로 남습니다.

초점focus
이 스레드가 무엇을 위한 것이고 무엇이 되면 끝나는가. 얼마나 왔는지가 아닙니다.
결정decision
앞으로 따를 선택. 이유와, 사람이 정했는지 에이전트가 정했는지가 붙습니다. 사람이 정한 것에는 그 말의 원문이 근거로 붙습니다.
제약constraint
지켜야 할 조건. 결정처럼 누가 정했는지가 붙습니다.
증거evidence
기계나 사람이 실제로 말한 것, 바이트 그대로. 테스트 출력, 에러, diff. 요약하지 않습니다.
노트note
에이전트가 단계마다 본 것과 결론. 해석이지 증거가 아닙니다. 네 종류가 있습니다.
바꿈확인발견생각
열린 문제open
아직 안 풀린 질문, 막힌 것, 불확실한 것.
다음next · owner
다음에 할 구체적인 일과 그 차례. 다음과 차례를 봅니다.
배제ruled out
지워진 가설. 지운 증거와, 그게 성립하는 범위가 같이 남습니다. 범위 밖에서는 다시 가설입니다.
용어term
작업 중에 지어 쓴 이름의 뜻. 그 자리에 없던 사람이 읽을 수 있게.

노트인가, 결정인가

세상이 뒤집을 수 있으면 노트, 나만 바꿀 수 있으면 결정입니다. 가설은 결정이 아닙니다. 이 선만 지키면 기록이 낡지 않습니다.

고치지 않고 대체합니다

결정, 제약, 초점, 다음은 고쳐 쓰지 않습니다. 새 것이 옛 것을 대체하고, 옛 것은 “무엇이 대체했는지”와 함께 남습니다. 그래서 회고에서 방향이 바뀐 자리를 그대로 볼 수 있습니다.

사람만 줄 수 있는 것

  • 판정. “이거 됐다 / 아니다”. 기계는 시도한 것까지만 압니다.
  • 결정. 대화 중에 정하면 “사용자가 정함”으로 남고, 나중에 뒤집을 수 있는 것도 사람뿐입니다.
  • 주제 이름. 새 일감의 이름은 사람 머릿속에만 있습니다.

멈출 때 가장 중요한 두 줄: 다음에 무엇을 하고, 그게 누구 차례인가.

에이전트는 단계를 마칠 때마다 다음을 남기고, 다음에는 반드시 차례가 붙습니다. 차례가 없으면 서버가 다음을 받지 않습니다.

차례뜻현황에서
user사람이 해야 합니다. 판정, 결정, 확인.내 차례
claude · codex …그 에이전트가 할 일입니다.에이전트에게
watch할 일 없이 지켜보기만.관찰 중

사람 차례인 다음은 사람에게 하는 말로 씁니다. “사용자가 정한다”가 아니라 “정해 주세요”.

왜 빼먹을 수 없게 했나

차례가 없으면 내일 화면을 열었을 때 “내가 뭘 해야 하나, 아니면 기다리면 되나”를 매번 다시 판단해야 합니다. 낡은 다음도 같은 문제를 만듭니다. 다음 세션이 그걸 읽고 이미 끝난 일을 하러 갑니다. 그래서 에이전트는 바뀐 게 없어도 매 단계 다음을 다시 말합니다.

에이전트가 차례를 틀리게 잡을 수는 있습니다. 현황에서 이상하면 “그건 내 차례야” 한마디면 됩니다.

기록의 규칙은 에이전트의 기억이 아니라 서버가 지킵니다. 어기면 기록이 거절되고, 이유가 에이전트에게 돌아갑니다.

규칙왜
모든 글의 첫 줄은 제목입니다. 120칸 이내(한글은 2칸), 기록 번호나 커밋 해시 없이.사람이 화면에서 그 줄만 읽고 무슨 일인지 알아야 합니다.
제목 바로 아래 문단에도 기록 번호를 두지 않습니다.그 문단도 화면에서 읽힙니다. 번호는 뒤 문단이나 증거 링크로.
스레드는 주제 없이 열 수 없습니다. “미분류”도 안 됩니다.회고에서 일감별로 읽을 수 있어야 합니다.
다음에는 차례가 있어야 합니다.다음과 차례.
사람이 정했다고 남기려면 그 말의 원문이 붙어야 합니다.에이전트의 요약이 사람의 결정으로 둔갑하지 않게.
초점을 다시 선언하지 않고 노트가 15개 쌓이면 거절됩니다.한 스레드에 다른 일이 쌓이는 것을 막습니다.
가설을 지울 때는 지운 증거와 범위가 있어야 합니다.배제는 이후 조사를 멈추게 하므로 문턱이 더 높습니다.

Worktrail을 만든 사람이 평소에 치는 말입니다. 명령어가 따로 없어서, 평소 말투로 하면 됩니다.

말풍선은 실제 세션에서 친 말 그대로입니다. 스레드 번호만 예시 번호로 바꿨습니다.

open_thread → decide(사용자가 정함) → note_turn“권장으로” 같은 짧은 답도 사람이 정한 결정으로 남고, 그 말의 원문이 근거로 붙습니다.

근거를 물을 때

사람스레드 3번 보고 문제 분석 후 해결책좀 제시해줘. 쉽게 어떤 상황인지도 설명해줘.
사람근데 지금 10 스레드는 왜 미분류야? 어떤 근거로 이렇게 분류했는지만 알려줘.
사람이해했어. 이 얘기 casebook에 기록해줘
find → trail → inspect“왜 그랬지?”는 기록을 찾아 답합니다. 노트는 해석이라, 근거로 댈 때는 그 노트가 가리키는 증거 원문까지 엽니다.

끝낼 때

사람좋다. 잘 보인다. 이걸로 데모는 닫아도 될듯.
사람읽혔어. 3 닫고 디자인 스레드 열자
close_thread → open_thread충분한지는 사람의 판정이고, 그 판정이 스레드의 마지막 줄이 됩니다. 멈추기만 할 때는 닫지 않고 다음과 차례를 남깁니다.

에이전트를 바꾸거나 새 세션에 넘기는 말은 에이전트 섞어 쓰기와 새 세션에 넘기기에 있습니다.

Claude Code와 Codex가 같은 스레드를 읽고 씁니다. 한쪽이 남긴 다음을 다른 쪽이 이어받습니다.

이렇게 씁니다

사람이 작업은 코덱스한테 시키고 너한테 진행상황 물어보는 식으로.
사람6번 스레드 진행중인데 codex가 뭐라고 적어놨어?
사람코덱스 끝났대
resume · trail다른 에이전트가 남긴 결정, 노트, 증거, 커밋을 그대로 읽습니다. 누가 남겼는지도 기록에 있습니다.

폴더를 나누는 때

스레드 연결은 폴더마다 하나입니다.

  • 폴더가 다르면 서로 무관합니다.
  • 같은 폴더를 번갈아 쓰는 것은 괜찮습니다.
  • 같은 폴더에서 동시에 돌리면 기록이 한쪽 스레드로 붙습니다. 이때는 git worktree로 폴더를 나눕니다.

채팅 창에서 의견 구하기

호스팅 서버라면 claude.ai나 ChatGPT에서도 커넥터로 같은 스레드를 읽을 수 있습니다. 코드 에이전트가 정리한 스레드를 두고 다른 모델에게 의견을 물을 때 씁니다.

사람이거 스레드 열어서 gpt웹이나 클로드 웹에도 의견 구할 수 있게 만들어줘. 물어보고 올게.

인계문을 따로 만들지 않습니다. 스레드가 인계문입니다.

대화가 너무 길어졌거나 새 세션에서 깨끗하게 시작하고 싶을 때, 에이전트에게 스레드를 기준으로 한 짧은 의뢰문을 쓰게 하고 그것을 새 세션의 첫 말로 붙여 넣습니다.

사람이거 새 세션 열어서 하고 싶어 우리는 세션 인계문을 만들 필요 없이 스레드가 있으니 그거 기준으로 작업 설계 의뢰문을 써줘
에이전트가 쓴 의뢰문 · 새 세션의 첫 말12번 스레드 resume 해서 이어서 하자. open 에 정할 것 다섯이 적혀 있다. 하나씩 물어봐 주고, 내가 답하면 결정으로 못 박은 뒤에 구현해라.

의뢰문에 담을 것

스레드 번호와 “무엇을 할지”만 담으면 됩니다. 결정, 제약, 열린 문제, 다음은 새 세션이 resume으로 직접 받습니다. 의뢰문에 옮겨 적으면 오히려 두 벌이 되어 어긋납니다.

대화가 요약될 때

요약에만 남은 관찰은 사라진 것이나 같습니다. Claude Code는 요약 직후 “먼저 기록하라”고 에이전트에게 알립니다. 훅이 없는 에이전트라면 긴 세션 중간에 “여기까지 기록해”라고 합니다.

정리가 필요할 때

어디까지 왔는지 한눈에 보고 싶으면 에이전트에게 정리를 청합니다. 에이전트는 사람이 물었을 때만 정리 도구(handoff)를 씁니다. 자기 기억을 되살리려고 쓰지 않습니다.

평소에는 필요 없습니다. 눈에 거슬릴 때만 씁니다.

이럴 때이렇게
한 스레드에 다른 얘기가 쌓일 때이건 새 스레드로
중요한 출력이 그냥 지나갈 때그거 기록해
차례를 잘못 잡았을 때그건 내 차례야 · 코덱스한테 넘긴 거야
키·비밀번호가 화면에 있을 때그건 기록하지 마
대화가 길어질 때 (훅 없는 에이전트)여기까지 기록해
주제가 겹쳐 보일 때이 두 주제 합쳐줘

현황은 지금을, 회고는 거기까지 온 길을 보여 줍니다. 화면은 읽기 전용입니다.

현황

“지금 뭘 해야 하나.” 열린 스레드를 차례별로 봅니다. 왼쪽에서 걸러 봅니다.

거르기보이는 것
내 차례사람이 판정하거나 정해야 하는 스레드. 하루를 시작하는 가장 빠른 길입니다.
에이전트에게에이전트가 이어 할 스레드.
관찰 중할 일 없이 지켜보는 스레드.
미정차례가 안 정해진 스레드.
오늘 바뀐 것오늘 기록이 생긴 스레드.

스레드를 열면 세 줄로 읽힙니다. 어디까지 왔는지, 다음은 무엇인지, 왜 그런지. 증거와 노트를 누르면 원문과 결론을 각각 펼쳐 봅니다.

회고

“이 주제가 어떻게 여기까지 왔나.” 한 주제의 결정과 사건을 시간순으로 봅니다. 결정이 왜 그렇게 났는지 되짚을 때 씁니다. 양이 많아서, 지금 할 일을 찾을 때는 현황이 낫습니다.

찾기

모든 스레드의 결정, 제약, 노트, 증거를 말로 찾습니다. 에이전트의 find와 같은 것을 사람이 봅니다.

과거 기록

설치 전에 한 작업에서 사람이 친 말만 가져와 둔 곳입니다(casebook-backfill). 에이전트의 말이나 도구 결과는 가져오지 않고, 현황·회고와 섞이지 않습니다.

데모에서 가상 팀의 4주치 기록으로 네 화면을 직접 볼 수 있습니다.

에이전트가 쓰는 도구입니다. 사람이 부를 일은 없고, 에이전트가 무엇을 하는지 읽을 때 참고합니다.

토큰이 얼마나 더 드나요?

기록하는 만큼 더 듭니다. 도구 설명과 세션 시작 요약이 세션마다 고정으로 들고, 호출마다 조금씩 듭니다. 가장 큰 것은 resume이라 세션에 한 번이면 됩니다. 긴 출력은 add_evidence_file로 파일째 남기고, 탐색이나 잡담에는 스레드를 열지 않으면 줄어듭니다.

비밀이 기록되면 어떡하나요?

증거는 원문 그대로 남습니다. 키나 비밀번호가 든 출력이 지나가면 “그건 기록하지 마”라고 합니다. 회사 코드가 섞이는 작업은 기록을 이 컴퓨터에만 둡니다.

누가 내 기록을 보나요?

로컬이면 나만 봅니다. 서버면 내 기록은 나에게만 보이지만, 한 서버 한 DB라 운영자는 볼 수 있습니다. 무엇을 보관하고 어떻게 지우는지는 신청 페이지에 적혀 있습니다.

지우려면?

로컬은 ~/.casebook/casebook.db 파일 하나를 지우면 끝입니다. 서버는 신청 페이지에 적힌 대로 요청합니다.

세션 시작에 스레드가 안 뜹니다

세션 시작 화면에 casebook hook … skipped가 뜨면 서버가 잠깐 안 닿은 것이고, 작업은 그대로 됩니다. 계속 안 붙으면 설치를 다시 실행합니다.

윈도우에서 되나요?

호스팅 서버로 씁니다. 신청 화면이 주는 지시문을 코딩 에이전트에게 붙여 넣으면 됩니다(윈도우). 기록을 이 컴퓨터에만 두는 방식은 설치기와 실행기가 sh라 WSL에서만 됩니다.
